# Display GitHub Actions pipeline evidence in the local dashboard

The dashboard now has a **CI pipeline evidence** panel below the manual feature-input/prediction form. It renders the structured report generated by `.github/workflows/ci.yml`.

## Automatic refresh from GitHub Actions

On push to `main`/`master` or a manual `workflow_dispatch`, the workflow publishes `latest-ci-risk-report.json` to the dedicated `ci-reports` branch. The dashboard's FastAPI endpoint reads that public raw-JSON feed and renders it in **CI pipeline evidence** whenever the UI opens or refreshes. Pull-request runs are deliberately not published. This requires the repository to be public and the workflow to have `contents: write` permission, which allows the built-in short-lived `GITHUB_TOKEN` to update only the dedicated report branch from the workflow. No GitHub token is sent to the browser.

The report branch contains only the generated JSON evidence file. It does not contain source code. The default workflow artifact and job summary remain available for detailed debugging.

## Manual import fallback

If the public feed is unavailable (for example, before the first publishing run, while offline, or for a private repository):

1. Open the repository's [Actions page](https://github.com/hardikgenie/deployment-risk-predictor/actions) and select the run you want to review.
2. Download the `ci-risk-evidence` artifact and unzip it.
3. Select `artifacts/ci-risk-report.json` (not `ruff-report.json`, `pip-audit.json`, or the markdown report) using **Import workflow report JSON** on the local dashboard at `http://127.0.0.1:8000`.
4. The UI displays run metadata, change-size statistics, test outcomes, Ruff findings, dependency vulnerabilities, Docker build outcome, demo model score, decision text, and measurement warnings.

The imported report is stored locally at `artifacts/dashboard_latest_ci_report.json` and is excluded from Git by `.gitignore`.

## Research-integrity boundary

The workflow's test, scan, change and Docker-build fields come from the CI run. The current model output is labelled synthetic-demo only. The UI does not turn that score into a validated deployment-failure probability. The current workflow does not deploy to production, and no model score overrides mandatory tests/container-build checks.
